# What Is Data Science?

Data is the starting point of Data Science.

Using data, we can create intelligence. Using intelligence, we can build systems that can:

- Learn from data
- Understand human language
- Generate content
- Make predictions
- Take actions

## Definition

**Data Science** is the process of collecting, cleaning, analyzing, and understanding data to make smart decisions.

### Simple Definition

> **Data Science means extracting useful information and insights from data.**

---

## Data Science Life Cycle

The Data Science life cycle generally contains the following steps:

### 1. Collect Data

Gather data from different sources such as:

- Files
- Databases
- Websites
- Sensors
- Applications
- APIs

### 2. Clean Data

Prepare the data by handling:

- Duplicate data
- Missing values
- Incorrect values
- Inconsistent data
- Unwanted information

### 3. Analyze Data

Study the data to identify:

- Patterns
- Trends
- Relationships
- Useful insights

### 4. Visualize Data

Represent data using:

- Charts
- Graphs
- Dashboards
- Reports

### 5. Build Model

Select and create a Machine Learning model based on the problem requirement.

### 6. Train Model

Train the model using historical data so that it can learn patterns and relationships.

### 7. Test Model

Evaluate the trained model using unseen data to check how accurately it performs.

### 8. Deploy Model

Make the trained model available for real-world or real-time usage in applications.

### 9. Monitor Results

Continuously monitor model performance and improve or retrain the model when required.

### Data Science Flow

**Collect Data → Clean Data → Analyze Data → Visualize Data → Build Model → Train → Test → Deploy → Monitor**

# What Is Machine Learning?

**Machine Learning (ML)** is a subset of Artificial Intelligence.

Machine Learning enables computers to learn patterns from data instead of requiring programmers to explicitly write rules for every possible situation.

## Simple Definition

> **Machine Learning is a technique where computers learn patterns from data and use those patterns to make predictions or decisions.**

In Machine Learning:

1. We provide data to the computer
2. A Machine Learning algorithm identifies patterns in the data
3. A model is created through training
4. The trained model makes predictions or decisions on new data

## Important Note

Machine Learning does not rely only on manually written fixed rules like traditional programming.

Instead, the model learns patterns from examples and historical data.

---

# Example 1: Cat and Dog Image Classification

Suppose we provide a Machine Learning model with many labeled pictures of cats and dogs.

During training:

1. The model processes the images
2. It learns patterns that help distinguish cats from dogs
3. After training, we provide a new image
4. The model predicts whether the image contains a cat or a dog

---

# Example 2: Email Spam Filter

In an email spam filtering system:

1. The Machine Learning model is trained using many emails
2. It learns patterns associated with spam and legitimate emails
3. When a new email arrives, the model analyzes it
4. It predicts whether the email is spam or not

# What Is Deep Learning?

**Deep Learning (DL)** is a subset of Machine Learning.

Deep Learning primarily uses **artificial neural networks with multiple layers** to learn complex patterns from data.

Deep Learning techniques are loosely inspired by the way biological neural systems process information.

They are especially powerful for complex data such as:

- Images
- Audio
- Video
- Text

### Relationship

**Artificial Intelligence → Machine Learning → Deep Learning**

# Machine Learning vs. Deep Learning

## Machine Learning

- Machine Learning is a subset of AI
- ML models learn patterns from data using algorithms
- Many ML algorithms work effectively with small to medium-sized datasets
- Commonly used with structured or tabular data
- Often requires manual feature engineering
- Training is generally less computationally expensive
- Many traditional ML models are easier to interpret

### Examples

- Linear Regression
- Logistic Regression
- Decision Trees
- Random Forest
- KNN
- SVM
- Naive Bayes

## Deep Learning

- Deep Learning is a subset of Machine Learning
- Uses neural networks with multiple layers
- Often benefits from large amounts of data
- Works particularly well with unstructured data
- Can automatically learn complex features from raw data
- Usually requires more computational resources
- GPUs are commonly used for training
- Powerful for complex AI problems

### Examples

- Artificial Neural Networks (ANN)
- Convolutional Neural Networks (CNN)
- Recurrent Neural Networks (RNN)
- LSTM
- Transformers

**Interpreter means:** It reads and executes code line by line.

## 4. Source Code Converts into Byte Code

Python source code is converted into byte code.

```text
Source Code → Byte Code
```

Source code means the code written by programmer.

Byte code is an intermediate code understood by Python Virtual Machine.

## 5. Byte Code Goes to PVM

PVM means Python Virtual Machine.

PVM executes the byte code.

```text
Byte Code → Python Virtual Machine → Output to User
```

![Ashokit AI image](./images/8.png)

## Python Program Execution Flow

1. **Source Code (`.py`)** → The Python code you write.

2. **Parsing & Syntax Check** → Python reads the code and checks whether the syntax is valid.

3. **AST (Abstract Syntax Tree)** → Python converts the code into a tree-like structure that represents the meaning and structure of the code.

4. **Compilation** → The AST is converted into bytecode.

5. **Bytecode** → Intermediate instructions that the Python Virtual Machine can understand.

6. **PVM (Python Virtual Machine)** → Reads and executes the bytecode.

7. **Output** → The final result is displayed.

---

### Simple Flow

```text
Source Code → Parse/Syntax Check → AST → Compile → Bytecode → PVM → Output
```

### For an Interview, Remember This One Line

> **Python parses the source code, creates an AST, compiles it into bytecode, and the PVM executes that bytecode to produce the output.**
(Parse simply means to read the code and break it down to understand its structure.)

## for loop vs while loop

---

1. Both for loop and while loop are used to execute a block of code repeatedly.
2. for loop is used when we know how many times the loop should run.
3. while loop is used when we do not know exactly how many times the loop will run.
4. for loop works with sequences like range, list, tuple, string, etc.
5. while loop works based on a condition.
6. In for loop, initialization and increment are handled automatically by range() or sequence.
7. In while loop, initialization and increment/decrement should be handled manually.
8. for loop is mostly used for fixed iterations.
9. while loop is mostly used for condition-based iterations.
10. for loop has less chance of infinite loop.
11. while loop has more chance of infinite loop if the condition is not updated properly.

| For Loop | While Loop |
|---|---|
| Used when the number of iterations is known. | Used when the number of iterations is unknown. |
| Works with sequences such as `range`, list, tuple, and string. | Works using a condition. |
| Iteration is handled automatically. | Initialization and update must be written manually. |
| Best for fixed/repeated items. | Best for condition-based repetition. |
| Less likely to create an infinite loop. | Can create an infinite loop if the condition is not updated. |

# Output: True
```

**Example Output:**

```text

JAVA Hash: 987654321

True
```

**Note:** The above hash numbers are only examples. The actual hash values may be different when the Python program is run again.

- `"Python"` gets a hash value.
- `"JAVA"` gets a different hash value.
- When `"Python"` appears again, it gets the same hash value during that program execution.
- Since `"Python"` is already present in the set, the duplicate value is not stored again.

# 6. Convert String into Uppercase Without Using upper()

**Concept:**

Every character has a numeric Unicode value.

For English letters:

- `ord()` returns the numeric value of a character.
- `chr()` converts a numeric value back into a character.

For basic English ASCII letters, the difference between lowercase and uppercase letters is `32`.

Example:

```text

```

```python
text = "python"

    else:
        result += ch

print(result)
# Output: PYTHON
```

# 9. Find the Most Repeated Character

# Function with Return Value

**The `return` keyword sends a result back from a function.**

```python

# return Keyword

**`return` is used to return a value from a function.**

**After the `return` statement executes, the function execution stops.**

**Any statement written after an executed `return` statement in the same block will not execute.**

```python
def test():
    print("Before return")
    return
    print("After return")
    # This line will never execute.

test()
# Output: Before return
```

### Explanation

- First, `"Before return"` is printed.
- `return` immediately exits the function.
- `"After return"` is never printed.
- Since `return` has no value, the function returns `None`.

### Example

```python
def test():
    print("Before return")
    return

result = test()
# Output: Before return

print(result)
# Output: None
```

# Positional Arguments

**In positional arguments, values are assigned to parameters based on their position.**

```python
def student(name, course):
    print("Name:", name)
    print("Course:", course)

student("Ashok", "Python")
# Output:
# Name: Ashok
# Course: Python
```

### Explanation

Here:

- First argument `"Ashok"` goes to `name`.
- Second argument `"Python"` goes to `course`.

**Important:** Order is important in positional arguments.

### Example

```python
def student(name, course):
    print("Name:", name)
    print("Course:", course)

student("Python", "Ashok")
# Output:
# Name: Python
# Course: Ashok
```

The program does not know that the values were given in the wrong logical order. It assigns them according to their positions.

---

# Keyword Arguments

**In keyword arguments, values are passed using parameter names.**

```python
def student(name, course):
    print("Name:", name)
    print("Course:", course)

student(course="JAVA", name="John")
# Output:
# Name: John
# Course: JAVA
```

### Explanation

- `course="JAVA"` directly assigns `"JAVA"` to `course`.
- `name="John"` directly assigns `"John"` to `name`.
- Because parameter names are specified, their order does not matter.

**Important:** Order is not important when passing keyword arguments.

---

# Default Arguments

**Default arguments are used to provide default values to parameters.**

**If a value is not passed, the default value will be used.**

```python
def enroll_student(name, course="GEN AI"):
    print("Student Name:", name)
    print("Enrolled Course:", course)

enroll_student("Ashok", "DEVOPS")
# Output:
# Student Name: Ashok
# Enrolled Course: DEVOPS

enroll_student("Steve")
# Output:
# Student Name: Steve
# Enrolled Course: GEN AI
```

### Explanation

For:

```python
enroll_student("Ashok", "DEVOPS")
```

`"DEVOPS"` is provided, so it replaces the default value `"GEN AI"`.

For:

```python
enroll_student("Steve")
```

No course is provided, so Python uses the default value `"GEN AI"`.

### Important Note

**A parameter with a default value must come after parameters without default values.**

Correct:

```python
def student(name, course="Python"):
    print(name, course)

student("Ashok")
# Output: Ashok Python
```

Incorrect:

```python

# Variable Length Arguments

Sometimes we do not know how many values will be passed to a function.

For example:

```text
add(10, 20)
add(10, 20, 40)
add(19, 78, 79, 797)
```

**Variable length arguments are used when we do not know how many positional values will be passed.**

**We use `*args` for variable length positional arguments.**

---

## *args: Variable-Length Arguments

```python
def print_numbers(*args):
    print(args)

print_numbers(10)
# Output: (10,)

print_numbers(20, 30)
# Output: (20, 30)

print_numbers(30, 40, 50)
# Output: (30, 40, 50)
```

### Explanation

- `*args` can receive any number of positional arguments.
- Python stores the received values in a **tuple**.
- The name `args` is commonly used by convention.

**Note:** `*args` stores values in tuple format.

---

# Sum of Numbers Using Variable Length Arguments

```python
def add_numbers(*args):
    total = 0

    for num in args:
        total = total + num

    return total

print(add_numbers(10, 20))
# Output: 30

print(add_numbers(10, 20, 30))
# Output: 60

print(add_numbers(10, 20, 30, 40))
# Output: 100
```

### Explanation

- `*args` collects all the numbers into a tuple.
- The `for` loop reads each number.
- Each number is added to `total`.
- `return total` sends the final total back.

---

## *args with a Keyword-Only Parameter

**Parameters written after `*args` are keyword-only parameters and must be passed using their parameter names.**

```python
def print_numbers(*args, model):
    print(args, model)

print_numbers(10, model="gpt")
# Output: (10,) gpt

print_numbers(20, 30, model="gpt")
# Output: (20, 30) gpt

print_numbers(30, 40, 50, model="gpt")
# Output: (30, 40, 50) gpt
```

### Explanation

Here:

- `*args` collects `10`, `20`, `30`, etc. into a tuple.
- `model` comes after `*args`.
- Therefore, `model` is a **keyword-only parameter**.
- We must pass it using `model="gpt"`.

**Note:** After `*args`, we can define keyword-only parameters.

msg = "Welcome to JAVA"

# Example 2: Generate Bill Receipt for Student Course Payment

```python
def process_payment(student_name, course_fee, paid_amount):

    def validate_payment():
        if paid_amount <= 0:
            return False

        if paid_amount > course_fee:
            return False

        return True

    def calculate_balance():
        return course_fee - paid_amount

    def generate_receipt(balance):
        print("Payment Receipt")
        print("----------------")
        print("Student Name:", student_name)
        print("Course Fee:", course_fee)
        print("Paid Amount:", paid_amount)
        print("Balance:", balance)

    if validate_payment():
        balance = calculate_balance()
        generate_receipt(balance)
    else:
        print("Invalid Payment")


process_payment(
    student_name="Ashok",
    course_fee=12000,
    paid_amount=5000
)

# Output:
# Payment Receipt
# ----------------
# Student Name: Ashok
# Course Fee: 12000
# Paid Amount: 5000
# Balance: 7000
```

### Explanation

`process_payment()` is the outer function.

It contains three nested functions:

1. `validate_payment()`
2. `calculate_balance()`
3. `generate_receipt()`

**Checks whether the payment amount is valid.**

    if paid_amount > course_fee:
        return False

```

- Payment cannot be `0` or negative.
- Payment cannot be greater than the course fee.
- If both conditions are valid, it returns `True`.

### calculate_balance()

**Calculates the remaining course fee.**

```python

    return course_fee - paid_amount
```

For this example:

```text

```

### generate_receipt()

**Displays the payment information and remaining balance.**

`validate_payment()`, `calculate_balance()`, and `generate_receipt()` are nested functions because they are defined inside `process_payment()`.

# Requirement: Shopping Cart Bill Calculation

When a customer places an order, we need to:

1. Calculate Total Cart Amount
2. Apply Discount
3. Add Delivery Charges
4. Generate Final Bill

### Discount Rules

- If `cart_amount >= 5000`, apply `2%` discount.
- If `cart_amount >= 3000`, apply `1%` discount.
- Otherwise, no discount.

### Delivery Charge Rule

- If `cart_amount >= 1000`, delivery charge is `0`.
- Otherwise, delivery charge is `50 INR`.

---

## Shopping Cart Bill Calculation

```python
cart_amount = float(input("Enter cart amount: "))

# Apply Discount
if cart_amount >= 5000:
    discount_percentage = 2
elif cart_amount >= 3000:
    discount_percentage = 1
else:
    discount_percentage = 0

discount_amount = cart_amount * discount_percentage / 100
amount_after_discount = cart_amount - discount_amount

# Add Delivery Charges
if cart_amount >= 1000:
    delivery_charge = 0
else:
    delivery_charge = 50

# Generate Final Bill
final_bill = amount_after_discount + delivery_charge

print("\n------ Shopping Cart Bill ------")
print("Cart Amount:", cart_amount)
print("Discount:", discount_amount)
print("Delivery Charge:", delivery_charge)
print("Final Bill:", final_bill)

# If input is 5000
# Output:
# ------ Shopping Cart Bill ------
# Cart Amount: 5000.0
# Discount: 100.0
# Delivery Charge: 0
# Final Bill: 4900.0
```

### Explanation

If the cart amount is `5000`:

**Step 1: Calculate Discount**

```text
2% of 5000 = 100
```

**Step 2: Amount After Discount**

```text
5000 - 100 = 4900
```

**Step 3: Delivery Charge**

Since the cart amount is greater than or equal to `1000`:

```text
Delivery Charge = 0
```

**Step 4: Final Bill**

```text
4900 + 0 = 4900
```

Therefore:

```text
Final Bill = 4900
```

# Function with Type Hints

**Type hints indicate the expected data types of function parameters and return values.**

```python
def f2(a: int, b: int) -> int:
    return a + b

result = f2(10, 20)

print(result, type(result))
# Output: 30 <class 'int'>
```

### Explanation

In:

```python
def f2(a: int, b: int) -> int:
```

- `a: int` indicates that `a` is expected to be an integer.
- `b: int` indicates that `b` is expected to be an integer.
- `-> int` indicates that the function is expected to return an integer.

However, Python does not automatically enforce these type hints at runtime.

For example:

```python
def f2(a: int, b: int) -> int:
    return a + b

result = f2("Hi", "Hello")

print(result, type(result))
# Output: HiHello <class 'str'>
```

### Why Does This Work?

Even though the function says:

```python
a: int
b: int
-> int
```

Python still allows strings to be passed.

Because:

```python
"Hi" + "Hello"
```

is valid string concatenation.

Therefore:

```text
Hi + Hello = HiHello
```

### Important Note

**Type hints are mainly used to help developers, IDEs, code editors, and type-checking tools understand the expected data types.**

**Python does not automatically enforce type hints during normal runtime execution.**

# Constructor

# Instance Methods

self.marks > 35

# Static Method

**A static method is a method logically related to a class but does not automatically receive `self` or `cls`.**

```

    @staticmethod
    def m1():

# Output: m1 method called...
```

### Explanation

`m1()` does not require:

```python
self
```

because it does not depend on a particular object's data.

# Multiple Inheritance

**One child class inherits from multiple parent classes.**

```text
Father     Mother
   \       /
      Child
```

Python uses **MRO — Method Resolution Order** to determine where methods should be searched.

---

## Example

```python
class Father:

    def father_property(self):
        print("Father property")

    def m1(self):
        print("Father m1 method")


class Mother:

    def mother_property(self):
        print("Mother property")

    def m1(self):
        print("Mother m1 method")


class Child(Father, Mother):

    def child_property(self):
        print("Child property")

    def m1(self):
        print("Child m1 method")


obj = Child()


obj.father_property()
# Output: Father property

obj.mother_property()
# Output: Mother property

obj.child_property()
# Output: Child property

obj.m1()
# Output: Child m1 method
```

`Child` has its own `m1()`.

Therefore, Python finds it first and executes it.

---

![Ashokit AI image](./images/18.png)

# MRO - Method Resolution Order

**MRO determines the order Python follows when searching for methods in an inheritance hierarchy.**

For:

```python
class Child(Father, Mother):
```

the simple inheritance hierarchy above gives:

```text
Child
  ↓
Father
  ↓
Mother
  ↓
object
```

We can check the actual MRO:

```python
print(Child.mro())

# Example Output:
# [<class '__main__.Child'>,
#  <class '__main__.Father'>,
#  <class '__main__.Mother'>,
#  <class 'object'>]
```

### Concept Connection

MRO becomes especially important when using:

```python
super()
```

because `super()` follows the MRO.

Structure:

```text
        A
       / \
      B   C
       \ /
        D
```

Here:

```text

```

```text

# `super()`

**`super()` is used to access the next appropriate implementation in the inheritance/MRO chain.**

For simple single inheritance, you can initially understand it as:

```text
super() → Access Parent Behaviour
```

More accurately:

```text
super() → Follow MRO to the next implementation
```

---

# `super()` with Method

```python
class Parent:

    def display(self):
        print("Parent display method")


class Child(Parent):

    def display(self):
        print("Child display method")


obj = Child()

obj.display()

# Output:
# Child display method
```

Because the child overrides `display()`, only the child implementation executes.

To execute inherited behaviour as well:

```python
class Parent:

    def display(self):
        print("Parent display method")


class Child(Parent):

    def display(self):
        super().display()
        print("Child display method")


obj = Child()

obj.display()

# Output:
# Parent display method
# Child display method
```

### Explanation

```python
super().display()
```

calls the next `display()` implementation according to MRO.

Then:

```python
print("Child display method")
```

continues the child method.

### Concept Connection

This repeats:

```text
Inheritance
+
Method Overriding
+
MRO
+
super()
```

# `super()` with Constructor

```python
class Person:

    def __init__(self, name):
        self.name = name


class Student(Person):

    def __init__(self, name, course):
        super().__init__(name)
        self.course = course

    def display(self):
        print(self.name)
        print(self.course)


s1 = Student("Ashok", "Python")

s1.display()

# Output:
# Ashok
# Python
```

### Explanation

The child defines its own constructor:

```python
Student.__init__()
```

Inside it:

```python
super().__init__(name)
```

runs the next constructor according to MRO.

In this example, that is:

```python
Person.__init__()
```

which initializes:

```python
self.name
```

Then:

```python
self.course = course
```

initializes the child-specific data.

### Concept Connection

This example combines earlier concepts:

```text
Constructor
+
Instance Variables
+
Inheritance
+
super()
```

# Abstract Method

**An abstract method is a method marked using `@abstractmethod`.**

It defines behaviour that concrete child classes are required to implement before they can be instantiated.

```python
from abc import ABC, abstractmethod


class Payment(ABC):

    @abstractmethod
    def pay(self, amount):
        pass

# Output:
# No output
```

### Important Correction

A common beginner definition is:

```text
Abstract Method = Method without body
```

That is not completely correct in Python.

The more accurate definition is:

```text
Abstract Method
      ↓
Method marked with @abstractmethod
```

An abstract method can technically contain code.

`pass` is commonly used when no implementation is required in the abstract method itself.

# Concrete Method

**A concrete method is a normal implemented method that already provides usable behaviour.**

```python

    print("Payment is successful. Thank you!")

# Abstract Method vs Concrete Method

| Abstract Method | Concrete Method |
|---|---|
| Marked with `@abstractmethod` | Normal implemented method |
| Defines required behaviour | Provides usable behaviour |
| Concrete child must satisfy the abstract requirement | Child can directly inherit it |
| Can technically contain code | Contains implementation |

# Python Exception Handling

---

## What is an Exception?

An **exception** is an unexpected event or error that occurs while a program is running and interrupts the normal flow of program execution.

If an exception occurs and we do not handle it, Python normally stops the program at that point.

```text
Normal Program Flow
        ↓
Exception Occurs
        ↓
Exception is not handled
        ↓
Program stops abnormally
```

As programmers, we can use **exception handling** to deal with expected runtime problems gracefully.

### Simple Meaning

```text
Exception
    ↓
Problem that occurs while the program is running
```

Example:

```python
a = 10
b = 0

result = a / b

print("Result:", result)

# Output:
# ZeroDivisionError: division by zero
```

Python cannot divide `10` by `0`, so it raises a `ZeroDivisionError`.

Because the exception is not handled:

```python
print("Result:", result)
```

is never executed.

---

# Why Exception Handling?

Exception handling is useful for:

1. Handling runtime problems
2. Preventing unexpected program termination
3. Displaying meaningful error messages
4. Allowing the program to continue where appropriate
5. Performing cleanup operations
6. Handling invalid user input
7. Handling missing files or unavailable resources
8. Creating application-specific errors

---

# Important Correction

It is common for beginners to say:

```text
Exception = Runtime Error
```

This is useful as a simple starting point, but more accurately:

```text
Exception
    ↓
An event represented by an exception object that interrupts normal execution
```

Also, Python has an actual built-in exception class named:

```python
RuntimeError
```

So we should not confuse the general term **runtime error** with the specific `RuntimeError` class.

---

# Types of Programming Problems

At a beginner level, we can divide common problems into:

1. Syntax Errors
2. Exceptions during execution
3. Logical Errors

---

# 1. Syntax Error

A **syntax error** occurs when Python code does not follow Python's grammar.

Example:

```python
# Incorrect code

# print("Hello

# Output:
# SyntaxError: '(' was never closed
```

Python cannot properly parse the program.

### Important

Syntax errors generally must be corrected before that code can run.

For example:

```python
print("Hello")
# Output: Hello
```

### Can `try-except` Handle a Syntax Error in the Same Invalid Code?

Normally, no.

For example, this program itself cannot start correctly:

```python
# try:
#     print("Hello
# except SyntaxError:
#     print("Syntax problem")
```

Python must first parse the source code before executing it.

So malformed syntax must normally be fixed manually.

---

# 2. Runtime Exception

A runtime exception occurs while otherwise valid Python code is executing.

Example:

```python
a = 10
b = 0

print(a / b)

# Output:
# ZeroDivisionError: division by zero
```

The syntax is valid.

The problem happens only when Python performs:

```python
10 / 0
```

Runtime exceptions can often be handled using:

```python
try
except
```

---

# 3. Logical Error

A logical error is different.

The program runs successfully, but produces the wrong result because the logic is incorrect.

Example:

```python
price = 100
quantity = 2

total = price + quantity

print(total)
# Output: 102
```

There is no exception.

But if we intended:

```text
Total = Price × Quantity
```

then the correct code should be:

```python
price = 100
quantity = 2

total = price * quantity

print(total)
# Output: 200
```

### Important

Exception handling does not automatically detect logical mistakes.

---

```

```text

```

```text
# Output:
# 10
```

But if the input is:

```text
abc
```

Python tries:

```python
int("abc")
```

which is not a valid integer conversion.

```text
# Output:
# ValueError: invalid literal for int() with base 10: 'abc'
```

### Concept Connection

```text

   ↓

   ↓
Conversion
   ↓

   ↓

# `TypeError`

A `TypeError` occurs when an operation is performed on incompatible types or a function receives an inappropriate type.

Example:

```python
result = "10" + 20

print(result)

# Output:
# TypeError: can only concatenate str (not "int") to str
```

Here:

```text
"10" → str
20   → int
```

Python cannot directly perform:

```python
str + int
```

Correct versions include:

```python
result = "10" + str(20)

print(result)
# Output: 1020
```

or:

```python
result = int("10") + 20

print(result)
# Output: 30
```

# `IndexError`

An `IndexError` occurs when we try to access an index that does not exist in a sequence such as a list, tuple, or string.

```python

# Output:
# IndexError: list index out of range
```

Available indexes are:

```text
0 → 10
1 → 20
2 → 30
```

Index `5` does not exist.

        ↓

        ↓

# `KeyError`

A `KeyError` occurs when we access a dictionary key that does not exist.

```python

    "name": "Ashok",
    "course": "GEN AI"

```

The available keys are:

```text

```

```text

### Safer Dictionary Access

The `.get()` method can be used when a missing key is acceptable.

# Specific Exception vs Generic Exception

Prefer:

```python
except ValueError:
```

or:

```python
except ZeroDivisionError:
```

when you know which problem you expect.

A generic handler is:

```python
except Exception as e:
```

Example:

```python
try:
    risky_operation()

    print("Invalid value")

except ZeroDivisionError:
    print("Cannot divide by zero")

    print("Unexpected problem:", e)
```

### Important Rule

```text
Specific exceptions first
        ↓
Generic Exception last
```

Why?

Because:

```python

```

is a parent class for many built-in exceptions.

If the generic handler comes first:

```python
try:
    print(10 / 0)

except Exception:
    print("Generic exception")

except ZeroDivisionError:
    print("Cannot divide by zero")
```

the specific `ZeroDivisionError` handler becomes unreachable for that exception because the broader `Exception` handler already catches it.

# Important Points

- An exception interrupts normal program flow.
- An unhandled exception normally terminates the program.
- Exception handling helps programs respond gracefully to runtime problems.
- `try` contains code that may raise an exception.
- `except` handles matching exceptions.
- `else` executes when the `try` block completes successfully.
- `finally` is used for cleanup and executes as part of the final exception-handling flow.
- `raise` is used to raise an exception manually.
- `Exception` is the common parent class for most application-level built-in exceptions.
- Handle specific exceptions before generic exceptions.
- Prefer meaningful exception types.
- Avoid bare `except:` in normal application code.
- Syntax errors usually need to be corrected before the program can execute.
- `IndentationError` is a type of `SyntaxError`.
- A missing dictionary key can raise `KeyError`.
- An invalid sequence index can raise `IndexError`.
- Invalid conversion can raise `ValueError`.
- Incompatible types can raise `TypeError`.
- Missing variables can raise `NameError`.
- Missing attributes can raise `AttributeError`.
- Missing files can raise `FileNotFoundError`.
- `ModuleNotFoundError` is related to `ImportError`.

- Exception objects can be stored using `as e`.

- Catch only exceptions that you know how to handle appropriately.

## **What is Race Condition**
---
**When multiple threads try to access and modify shared data at the same time may produce an incorrect result which is called as Race Condition.**
Ex :
Consider a bank account.
Two threads are trying to withdraw money from the same account at the same.
---
```python
import threading
import time
balance = 1000
def withdraw(amount):
    global balance
    if balance >= amount:
        current_balance = balance
        time.sleep(1)
        balance = current_balance - amount
        print("Withdraw successfully")
        print("Remaining Balance:", balance)
    else:
        print("Insufficient Balance")
t1 = threading.Thread(target=withdraw, args=(700,))
t2 = threading.Thread(target=withdraw, args=(700,))
t1.start()
t2.start()
t1.join()
t2.join()
print("Final Balance :", balance)

Correct output:
Withdrawal successful
Remaining Balance: 300
Insufficient balance
Final Balance: 300
with lock: allows only one thread to check and update balance at a time.

lock is like a key for the shared balance variable.
lock = threading.Lock()
When a thread enters this block:
with lock:
it takes the key. Other threads must wait until the current thread leaves that block.
with lock:
    if balance >= amount:
        balance = balance - amount
Step by step:
1. t1 enters with lock: and locks the balance.
2. t2 reaches with lock: but must wait.
3. t1 withdraws 700; balance becomes 300.
4. t1 exits the block and releases the lock.
5. t2 enters the block and checks balance.
6. 300 >= 700 is False, so it prints "Insufficient balance".
with lock: automatically releases the lock, even if an error occurs inside the block.
```
---
**Both threads may read the original balance as 1000.**
**Both threads may then allow a withdrawal of 700.**
**This creates incorrect account processing.**
**The exact result depends on thread scheduling, which makes race-condition bugs difficult to**
reproduce.

## **What is Thread Synchronization**
---
**Thread synchronization means controlling multiple threads so that only one thread accesses a**
critical shared resource at a time.
**Python provides synchronization tools such as:**
    -- Lock
    -- RLock
    -- Semaphore
    -- Event
    -- Condition
Note: For beginners, the most important tool is Lock.
**A Lock allows only one thread at a time to execute a protected section of code.**
```python
lock = threading.Lock()
**Before accesing shared resource we need to accquire lock like below**
lock.accquire()
**After completing the work we need to release the lock like below**
lock.release()
```
---
```python
import threading
import time
balance = 1000
lock = threading.Lock()
def withdraw(amount):
    global balance
    lock.acquire()
    try:
        if balance >= amount:
            print(
                threading.current_thread().name,
                "is processing withdrawl"
            )
            current_balance = balance
            time.sleep(1)
            balance = current_balance - amount
            print("Remaining Balance:", balance)
        else:
            print("insufficient balance")
    finally:
        lock.release()
t1 = threading.Thread(target=withdraw, args=(700,), name="Customer-1")
t2 = threading.Thread(target=withdraw, args=(700,), name="Customer-2")
t1.start()
t2.start()
t1.join()
t2.join()
print("Final Balance:", balance)

Expected output:
Customer-1 is processing withdrawal
Remaining Balance: 300
Customer-2 - Insufficient balance
Final Balance: 300
finally ensures lock.release() runs even if an error occurs while processing the withdrawal.
```

---

    connection = get_connection()

    query = """
        CREATE TABLE IF NOT EXISTS students (

            name VARCHAR(100) NOT NULL,

def create_student(student):
    conn = get_connection()
    cursor = conn.cursor()

    query = "INSERT INTO students(name, course, fee) VALUES(%s, %s, %s)"

    cursor.execute(
        query,
        (student.name, student.course, student.fee)
    )

    conn.commit()

    cursor.close()
    conn.close()

    return {

def get_students():

## **What is DataFrame?**
---

**DataFrame is a two-dimensional data structure in Pandas.**

**It stores data in rows and columns.**

```python

import pandas as pd

students = {
    "Name": ["Ravi", "Sita", "Kiran", "Rahul", "Priya"],
    "Course": ["Python", "Java", "Python", "DevOps", "Python"],
    "Marks": [85, 90, 75, 60, 95]
}

df = pd.DataFrame(students)

print(df[df["Course"] == "Python"])

# 2. Show students with marks greater than 80
print(df[df["Marks"] > 80])

# Module 4: S3 - Simple Storage Service

## 4.1 What is S3?

S3 is an object storage service offering unlimited storage with 99.999999999% (11 nines) durability.

### Real-World Analogy
- **S3 Bucket** = A filing cabinet (container)
- **S3 Object** = A file in the cabinet (any file type, up to 5TB)
- **S3 Key** = The file's full path/name (e.g., `photos/2024/vacation.jpg`)

### S3 Architecture

```
┌──────────────────────────────────────────────┐
│              S3 (Global Service)              │
│                                               │
│  ┌─────────────────────────────────────────┐ │
│  │  Bucket: my-company-website              │ │
│  │  (Region: us-east-1)                     │ │
│  │                                          │ │
│  │  ├── index.html          (Object)        │ │
│  │  ├── css/style.css       (Object)        │ │
│  │  ├── images/logo.png     (Object)        │ │
│  │  └── data/report.pdf     (Object)        │ │
│  └─────────────────────────────────────────┘ │
│                                               │
│  ┌─────────────────────────────────────────┐ │
│  │  Bucket: my-company-backups              │ │
│  │  (Region: eu-west-1)                     │ │
│  │                                          │ │
│  │  ├── db/2024-01-15.sql.gz               │ │
│  │  └── logs/app-2024-01.tar.gz            │ │
│  └─────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

### Key Facts
- Bucket names are **globally unique** across all AWS accounts
- Objects can be 0 bytes to 5 TB
- Unlimited total storage
- Flat structure (folders are just key prefixes)

## 4.2 S3 Storage Classes

| Class | Durability | Availability | Min Duration | Use Case |
|-------|-----------|-------------|-------------|----------|
| **S3 Standard** | 11 nines | 99.99% | None | Frequently accessed data |
| **S3 Intelligent-Tiering** | 11 nines | 99.9% | None | Unknown access patterns |
| **S3 Standard-IA** | 11 nines | 99.9% | 30 days | Infrequent access |
| **S3 One Zone-IA** | 11 nines | 99.5% | 30 days | Reproducible infrequent data |
| **S3 Glacier Instant** | 11 nines | 99.9% | 90 days | Archive with instant access |
| **S3 Glacier Flexible** | 11 nines | 99.99% | 90 days | Archive (minutes to hours) |
| **S3 Glacier Deep Archive** | 11 nines | 99.99% | 180 days | Long-term archive (12 hours) |

### Cost Comparison (us-east-1, per GB/month)
```
S3 Standard:           $0.023
S3 Standard-IA:        $0.0125
S3 One Zone-IA:        $0.01
S3 Glacier Instant:    $0.004
S3 Glacier Flexible:   $0.0036
S3 Glacier Deep:       $0.00099
```

## 4.3 Bucket Operations

### Manual Steps via AWS Console: Create and Use S3 Bucket

**Create a bucket:**
1. Go to **S3 → Buckets → Create bucket**
2. Bucket name: `my-company-data-2024` (must be globally unique)
3. Region: `us-east-1`
4. Object Ownership: `ACLs disabled` (recommended)
5. Block Public Access: keep **all checked** (default, most secure)
6. Versioning: `Disable` (enable later if needed)
7. Encryption: `SSE-S3` (default, free)
8. Click **Create bucket**

**Upload files:**
1. Click on your bucket name
2. Click **Upload** → **Add files** or **Add folder**
3. Select files from your computer
4. (Optional) Set storage class, encryption, metadata
5. Click **Upload**

**Download files:**
1. Click on the object name
2. Click **Download** or click **Open** to view in browser

**Create a folder:**
1. Inside the bucket, click **Create folder**
2. Name: `images/`
3. Click **Create folder**

**Delete objects:**
1. Select the objects (checkbox)
2. Click **Delete**
3. Type `permanently delete` to confirm → **Delete objects**

**Enable versioning:**
1. Go to bucket → **Properties** tab
2. Scroll to **Bucket Versioning** → **Edit**
3. Select **Enable** → **Save changes**

**Set up lifecycle rules:**
1. Go to bucket → **Management** tab
2. Click **Create lifecycle rule**
3. Name: `move-to-glacier-after-90-days`
4. Apply to all objects (or filter by prefix/tag)
5. Add transition: move to `Glacier Flexible Retrieval` after `90` days
6. Add expiration: permanently delete after `365` days (optional)
7. Click **Create rule**

**Enable static website hosting:**
1. Go to bucket → **Properties** tab
2. Scroll to **Static website hosting** → **Edit**
3. Select **Enable**
4. Index document: `index.html`
5. Error document: `error.html`
6. **Save changes**
7. Go to **Permissions** tab → **Block public access** → **Edit** → uncheck all → **Save**
8. Go to **Bucket policy** → **Edit** → paste a public read policy (see §4.6)

### Create a Bucket (CLI)

```bash
aws s3 mb s3://my-company-data-2024
```

**Command Breakdown:**
- `s3 mb` → "make bucket"
- `s3://my-company-data-2024` → Bucket name (must be globally unique)

**Expected Output:**
```
make_bucket: my-company-data-2024
```

```bash
# Create in a specific region
aws s3 mb s3://my-company-eu-data --region eu-west-1
```

### List Buckets

```bash
aws s3 ls
```

**Expected Output:**
```
2024-01-15 10:30:00 my-company-data-2024
2024-01-15 10:35:00 my-company-eu-data
```

### Delete a Bucket

```bash
# Must be empty first
aws s3 rb s3://my-company-eu-data

# Force delete (removes all objects first)
aws s3 rb s3://my-company-eu-data --force
```

## 4.4 Object Operations

### Upload Files

```bash
# Upload a single file
aws s3 cp myfile.txt s3://my-company-data-2024/

# Upload with a specific key (path)
aws s3 cp report.pdf s3://my-company-data-2024/reports/2024/report.pdf

# Upload an entire directory
aws s3 cp ./website/ s3://my-company-data-2024/website/ --recursive
```

**Expected Output:**
```
upload: ./myfile.txt to s3://my-company-data-2024/myfile.txt
upload: ./report.pdf to s3://my-company-data-2024/reports/2024/report.pdf
```

### Download Files

```bash
# Download a single file
aws s3 cp s3://my-company-data-2024/myfile.txt ./downloaded.txt

# Download an entire "folder"
aws s3 cp s3://my-company-data-2024/reports/ ./local-reports/ --recursive
```

### List Objects

```bash
# List all objects in bucket
aws s3 ls s3://my-company-data-2024/

# List recursively (all nested objects)
aws s3 ls s3://my-company-data-2024/ --recursive

# List with human-readable sizes
aws s3 ls s3://my-company-data-2024/ --recursive --human-readable --summarize
```

**Expected Output:**
```
2024-01-15 10:40:00    1.2 KiB myfile.txt
2024-01-15 10:41:00  256.3 KiB reports/2024/report.pdf

Total Objects: 2
   Total Size: 257.5 KiB
```

### Sync (Mirror local ↔ S3)

```bash
# Sync local directory to S3 (uploads only new/changed files)
aws s3 sync ./my-website/ s3://my-company-data-2024/website/

# Sync S3 to local
aws s3 sync s3://my-company-data-2024/website/ ./local-copy/

# Sync with delete (remove files in destination not in source)
aws s3 sync ./my-website/ s3://my-company-data-2024/website/ --delete

# Sync excluding certain files
aws s3 sync ./project/ s3://my-bucket/project/ --exclude "*.log" --exclude "node_modules/*"
```

### Move and Delete

```bash
# Move (rename) an object
aws s3 mv s3://my-bucket/old-name.txt s3://my-bucket/new-name.txt

# Delete a single object
aws s3 rm s3://my-bucket/myfile.txt

# Delete all objects with a prefix
aws s3 rm s3://my-bucket/logs/ --recursive

# Delete all objects in bucket
aws s3 rm s3://my-bucket/ --recursive
```

## 4.5 S3 Versioning

Versioning keeps multiple versions of an object, protecting against accidental deletion.

### Enable Versioning

```bash
aws s3api put-bucket-versioning \
  --bucket my-company-data-2024 \
  --versioning-configuration Status=Enabled
```

### Check Versioning Status

```bash
aws s3api get-bucket-versioning --bucket my-company-data-2024
```

**Expected Output:**
```json
{
    "Status": "Enabled"
}
```

### List Object Versions

```bash
aws s3api list-object-versions \
  --bucket my-company-data-2024 \
  --prefix myfile.txt
```

**Expected Output:**
```json
{
    "Versions": [
        {
            "Key": "myfile.txt",
            "VersionId": "3sL4kqtJlcpXroDTDmJ+rmSpXd3dIbrHY",
            "IsLatest": true,
            "LastModified": "2024-01-15T12:00:00+00:00",
            "Size": 1234
        },
        {
            "Key": "myfile.txt",
            "VersionId": "UIORUnfnc8EjSnq0AdUcz_iBR0o83tphC",
            "IsLatest": false,
            "LastModified": "2024-01-14T10:00:00+00:00",
            "Size": 1100
        }
    ]
}
```

### Restore a Previous Version

```bash
# Copy old version as the current version
aws s3api get-object \
  --bucket my-company-data-2024 \
  --key myfile.txt \
  --version-id UIORUnfnc8EjSnq0AdUcz_iBR0o83tphC \
  restored-file.txt

aws s3 cp restored-file.txt s3://my-company-data-2024/myfile.txt
```

## 4.6 S3 Bucket Policies

Bucket policies control access at the bucket level using JSON.

### Public Read Policy (Static Website)

```bash
cat > bucket-policy.json << 'EOF'
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::my-website-bucket/*"
        }
    ]
}
EOF

aws s3api put-bucket-policy \
  --bucket my-website-bucket \
  --policy file://bucket-policy.json
```

### Restrict Access to Specific IP

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowOfficeOnly",
            "Effect": "Deny",
            "Principal": "*",
            "Action": "s3:*",
            "Resource": [
                "arn:aws:s3:::my-private-bucket",
                "arn:aws:s3:::my-private-bucket/*"
            ],
            "Condition": {
                "NotIpAddress": {
                    "aws:SourceIp": "203.0.113.0/24"
                }
            }
        }
    ]
}
```

### Cross-Account Access

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "CrossAccountAccess",
            "Effect": "Allow",
            "Principal": {
                "AWS": "arn:aws:iam::987654321098:root"
            },
            "Action": [
                "s3:GetObject",
                "s3:ListBucket"
            ],
            "Resource": [
                "arn:aws:s3:::shared-data-bucket",
                "arn:aws:s3:::shared-data-bucket/*"
            ]
        }
    ]
}
```

## 4.7 S3 Static Website Hosting

### Enable Static Website Hosting

```bash
# Create website files
mkdir my-website
cat > my-website/index.html << 'EOF'
<!DOCTYPE html>
<html>
<head><title>My Company</title></head>
<body>
    <h1>Welcome to My Company</h1>
    <p>Hosted on Amazon S3</p>
</body>
</html>
EOF

cat > my-website/error.html << 'EOF'
<!DOCTYPE html>
<html>
<head><title>Error</title></head>
<body><h1>404 - Page Not Found</h1></body>
</html>
EOF

# Create bucket
aws s3 mb s3://my-company-website-2024

# Disable Block Public Access
aws s3api put-public-access-block \
  --bucket my-company-website-2024 \
  --public-access-block-configuration \
  "BlockPublicAcls=false,IgnorePublicAcls=false,BlockPublicPolicy=false,RestrictPublicBuckets=false"

# Enable website hosting
aws s3 website s3://my-company-website-2024/ \
  --index-document index.html \
  --error-document error.html

# Upload files
aws s3 sync my-website/ s3://my-company-website-2024/

# Apply bucket policy for public read
aws s3api put-bucket-policy \
  --bucket my-company-website-2024 \
  --policy '{
    "Version": "2012-10-17",
    "Statement": [{
        "Sid": "PublicRead",
        "Effect": "Allow",
        "Principal": "*",
        "Action": "s3:GetObject",
        "Resource": "arn:aws:s3:::my-company-website-2024/*"
    }]
  }'
```

**Website URL format:**
```
http://my-company-website-2024.s3-website-us-east-1.amazonaws.com
```

## 4.8 S3 Lifecycle Rules

Automatically transition or delete objects based on age.

```bash
cat > lifecycle.json << 'EOF'
{
    "Rules": [
        {
            "ID": "MoveToIA",
            "Status": "Enabled",
            "Filter": {"Prefix": "logs/"},
            "Transitions": [
                {
                    "Days": 30,
                    "StorageClass": "STANDARD_IA"
                },
                {
                    "Days": 90,
                    "StorageClass": "GLACIER"
                },
                {
                    "Days": 365,
                    "StorageClass": "DEEP_ARCHIVE"
                }
            ],
            "Expiration": {
                "Days": 730
            }
        }
    ]
}
EOF

aws s3api put-bucket-lifecycle-configuration \
  --bucket my-company-data-2024 \
  --lifecycle-configuration file://lifecycle.json
```

**What this does:**
```
Day 0-29:   logs/ stored in S3 Standard ($0.023/GB)
Day 30-89:  Auto-moved to Standard-IA ($0.0125/GB)
Day 90-364: Auto-moved to Glacier ($0.0036/GB)
Day 365-729: Auto-moved to Deep Archive ($0.00099/GB)
Day 730:    Auto-deleted
```

## 4.9 S3 Encryption

### Server-Side Encryption (SSE)

```bash
# Upload with SSE-S3 (Amazon managed keys)
aws s3 cp myfile.txt s3://my-bucket/ --sse AES256

# Upload with SSE-KMS (AWS KMS managed keys)
aws s3 cp myfile.txt s3://my-bucket/ --sse aws:kms

# Set default encryption for bucket
aws s3api put-bucket-encryption \
  --bucket my-bucket \
  --server-side-encryption-configuration '{
    "Rules": [{
        "ApplyServerSideEncryptionByDefault": {
            "SSEAlgorithm": "aws:kms"
        },
        "BucketKeyEnabled": true
    }]
  }'
```

## 4.11 S3 Multipart Upload

For files larger than 100MB, use multipart upload.

```bash
# AWS CLI automatically uses multipart for large files
# Configure thresholds:
aws configure set default.s3.multipart_threshold 64MB
aws configure set default.s3.multipart_chunksize 16MB

# Upload large file (CLI handles multipart automatically)
aws s3 cp large-database-backup.tar.gz s3://my-bucket/backups/
```

### Manual Multipart Upload (for programmatic control)

```bash
# 1. Initiate
UPLOAD_ID=$(aws s3api create-multipart-upload \
  --bucket my-bucket \
  --key large-file.zip \
  --query 'UploadId' --output text)

# 2. Upload parts
aws s3api upload-part \
  --bucket my-bucket \
  --key large-file.zip \
  --part-number 1 \
  --body part1.zip \
  --upload-id $UPLOAD_ID

# 3. Complete
aws s3api complete-multipart-upload \
  --bucket my-bucket \
  --key large-file.zip \
  --upload-id $UPLOAD_ID \
  --multipart-upload '{"Parts":[{"PartNumber":1,"ETag":"\"etag1\""}]}'
```

## 4.13 Industry Project: Media Company Asset Management

### Scenario
A media company needs to store, process, and serve images with automatic optimization.

```bash
#!/bin/bash
# === S3 Media Asset Management Setup ===

BUCKET="mediacompany-assets-2024"
REGION="us-east-1"

# --- Create buckets ---
aws s3 mb s3://$BUCKET --region $REGION
aws s3 mb s3://${BUCKET}-thumbnails --region $REGION

# --- Enable versioning (protect against accidental deletion) ---
aws s3api put-bucket-versioning \
  --bucket $BUCKET \
  --versioning-configuration Status=Enabled

# --- Set default encryption ---
aws s3api put-bucket-encryption \
  --bucket $BUCKET \
  --server-side-encryption-configuration '{
    "Rules": [{"ApplyServerSideEncryptionByDefault": {"SSEAlgorithm": "AES256"}}]
  }'

# --- Lifecycle rules ---
cat > /tmp/lifecycle.json << 'EOF'
{
    "Rules": [
        {
            "ID": "ArchiveOldAssets",
            "Status": "Enabled",
            "Filter": {"Prefix": "raw/"},
            "Transitions": [
                {"Days": 90, "StorageClass": "STANDARD_IA"},
                {"Days": 365, "StorageClass": "GLACIER"}
            ]
        },
        {
            "ID": "CleanupTempFiles",
            "Status": "Enabled",
            "Filter": {"Prefix": "temp/"},
            "Expiration": {"Days": 7}
        },
        {
            "ID": "CleanupIncompleteUploads",
            "Status": "Enabled",
            "Filter": {"Prefix": ""},
            "AbortIncompleteMultipartUpload": {"DaysAfterInitiation": 3}
        }
    ]
}
EOF

aws s3api put-bucket-lifecycle-configuration \
  --bucket $BUCKET \
  --lifecycle-configuration file:///tmp/lifecycle.json

# --- CORS configuration (for web uploads) ---
aws s3api put-bucket-cors \
  --bucket $BUCKET \
  --cors-configuration '{
    "CORSRules": [{
        "AllowedHeaders": ["*"],
        "AllowedMethods": ["GET", "PUT", "POST"],
        "AllowedOrigins": ["https://www.mediacompany.com"],
        "ExposeHeaders": ["ETag"],
        "MaxAgeSeconds": 3600
    }]
  }'

# --- Create folder structure ---
for folder in raw/ processed/ thumbnails/ temp/; do
  aws s3api put-object --bucket $BUCKET --key $folder
done

echo "Media asset management bucket configured!"
echo "Bucket: $BUCKET"
echo "Upload raw assets to: s3://$BUCKET/raw/"
```

## 4.14 Common Errors & Troubleshooting

### Error 1: "BucketAlreadyExists"
```
make_bucket failed: s3://my-bucket An error occurred (BucketAlreadyExists)
```
**Fix:** Bucket names are globally unique. Choose a different name:
```bash
aws s3 mb s3://my-bucket-$(date +%s)
```

### Error 2: "AccessDenied" on upload
```
upload failed: An error occurred (AccessDenied) when calling the PutObject operation
```
**Fix:**
```bash
# Check IAM permissions
aws iam simulate-principal-policy \
  --policy-source-arn arn:aws:iam::123456789012:user/myuser \
  --action-names s3:PutObject \
  --resource-arns arn:aws:s3:::my-bucket/*

# Check bucket policy
aws s3api get-bucket-policy --bucket my-bucket

# Check Block Public Access settings
aws s3api get-public-access-block --bucket my-bucket
```

### Error 3: "NoSuchBucket"
```
An error occurred (NoSuchBucket) when calling the ListObjects operation
```
**Fix:** Verify bucket exists and check spelling:
```bash
aws s3 ls | grep my-bucket
```

### Error 4: "EntityTooLarge" (file > 5GB)
```
An error occurred (EntityTooLarge): Your proposed upload exceeds the maximum allowed size
```
**Fix:** Use multipart upload:
```bash
aws configure set default.s3.multipart_threshold 64MB
aws s3 cp large-file.zip s3://my-bucket/
```

### Error 5: Static website returns 403
**Troubleshooting checklist:**
```bash
# 1. Check Block Public Access is disabled
aws s3api get-public-access-block --bucket my-bucket

# 2. Check bucket policy exists
aws s3api get-bucket-policy --bucket my-bucket

# 3. Check website configuration
aws s3api get-bucket-website --bucket my-bucket

# 4. Check object ACLs
aws s3api get-object-acl --bucket my-bucket --key index.html
```

## 4.15 S3 CORS (Cross-Origin Resource Sharing)

CORS allows a web page loaded from one S3 bucket to request resources from a different S3 bucket (different origin).

### When You Need CORS

If your S3-hosted website at `http://my-site.s3-website.us-east-1.amazonaws.com` fetches content from another bucket `http://other-bucket.s3-website.us-east-1.amazonaws.com`, the browser blocks the request unless CORS is configured on the **other bucket**.

### Configure CORS

```json
[
    {
        "AllowedHeaders": ["Authorization"],
        "AllowedMethods": ["GET"],
        "AllowedOrigins": ["http://my-site.s3-website.us-east-1.amazonaws.com"],
        "ExposeHeaders": [],
        "MaxAgeSeconds": 3000
    }
]
```

```bash
aws s3api put-bucket-cors \
  --bucket other-bucket \
  --cors-configuration file://cors-config.json
```

### HTML Example (fetching cross-origin content)

```html
<div id="tofetch"></div>
<script>
    fetch('http://other-bucket.s3-website.us-east-1.amazonaws.com/extra-page.html')
    .then((response) => response.text())
    .then((html) => {
        document.getElementById("tofetch").innerHTML = html;
    });
</script>
```

## 4.16 S3 MFA Delete

MFA Delete adds an extra layer of protection by requiring MFA authentication to permanently delete object versions or change versioning state.

### Requirements

- Versioning must be enabled on the bucket
- Only the **root account** can enable/disable MFA Delete
- MFA is required to: permanently delete an object version, suspend versioning
- MFA is NOT required to: enable versioning, list deleted versions

```bash
# Enable MFA Delete (must use root credentials)
aws s3api put-bucket-versioning \
  --bucket my-protected-bucket \
  --versioning-configuration Status=Enabled,MFADelete=Enabled \
  --mfa "arn:aws:iam::123456789012:mfa/root-mfa-device 123456" \
  --profile root-account

# Disable MFA Delete
aws s3api put-bucket-versioning \
  --bucket my-protected-bucket \
  --versioning-configuration Status=Enabled,MFADelete=Disabled \
  --mfa "arn:aws:iam::123456789012:mfa/root-mfa-device 789012" \
  --profile root-account
```

## 4.17 S3 Access Logs & Athena

S3 Server Access Logging records all requests made to a bucket. You can analyze these logs with Amazon Athena (serverless SQL).

### Enable Access Logging

```bash
aws s3api put-bucket-logging \
  --bucket my-source-bucket \
  --bucket-logging-status '{
    "LoggingEnabled": {
      "TargetBucket": "my-access-logs-bucket",
      "TargetPrefix": "logs/my-source-bucket/"
    }
  }'
```

**Warning:** Never set the logging bucket to the same bucket — it creates an infinite loop.

### Query Logs with Athena

```sql
-- Create database
CREATE DATABASE s3_access_logs_db;

-- Create table for S3 access logs
CREATE EXTERNAL TABLE IF NOT EXISTS s3_access_logs_db.mybucket_logs(
    BucketOwner STRING,
    Bucket STRING,
    RequestDateTime STRING,
    RemoteIP STRING,
    Requester STRING,
    RequestID STRING,
    Operation STRING,
    Key STRING,
    RequestURI_operation STRING,
    RequestURI_key STRING,
    RequestURI_httpProtoversion STRING,
    HTTPstatus STRING,
    ErrorCode STRING,
    BytesSent BIGINT,
    ObjectSize BIGINT,
    TotalTime STRING,
    TurnAroundTime STRING,
    Referrer STRING,
    UserAgent STRING,
    VersionId STRING,
    HostId STRING,
    SigV STRING,
    CipherSuite STRING,
    AuthType STRING,
    EndPoint STRING,
    TLSVersion STRING
)
ROW FORMAT SERDE 'org.apache.hadoop.hive.serde2.RegexSerDe'
```

## 4.18 S3 Replication (CRR & SRR)

S3 Replication copies objects between buckets automatically. Versioning must be enabled on both source and destination.

| Type | Full Name | Use Case |
|------|-----------|----------|
| **CRR** | Cross-Region Replication | Compliance, lower latency, DR |
| **SRR** | Same-Region Replication | Log aggregation, live replication between accounts |

### Enable Replication

```bash
# Create replication role
cat > replication-role.json << 'EOF'
{
    "Version": "2012-10-17",
    "Statement": [{
        "Effect": "Allow",
        "Principal": {"Service": "s3.amazonaws.com"},
        "Action": "sts:AssumeRole"
    }]
}
EOF

ROLE_ARN=$(aws iam create-role \
  --role-name S3ReplicationRole \
  --assume-role-policy-document file://replication-role.json \
  --query 'Role.Arn' --output text)

# Set replication configuration
aws s3api put-bucket-replication \
  --bucket source-bucket \
  --replication-configuration '{
    "Role": "'$ROLE_ARN'",
    "Rules": [{
      "Status": "Enabled",
      "Priority": 1,
      "Filter": {"Prefix": ""},
      "Destination": {
        "Bucket": "arn:aws:s3:::destination-bucket",
        "StorageClass": "STANDARD_IA"
      },
      "DeleteMarkerReplication": {"Status": "Enabled"}
    }]
  }'
```

### Replication Notes

- Only new objects are replicated after enabling (not retroactive)
- Use S3 Batch Replication for existing objects
- Delete markers can be replicated (optional)
- Permanent deletes (version ID) are NOT replicated (prevents malicious deletes)
- No chaining: if bucket A → B → C, objects in A are NOT replicated to C

## 4.19 S3 Object Lock & Glacier Vault Lock

### S3 Object Lock

Prevents object deletion for a specified retention period. Requires versioning.

| Mode | Description |
|------|-------------|
| **Governance** | Users with special permissions can override/delete |
| **Compliance** | Nobody can override or delete, not even root |

```bash
# Enable Object Lock on bucket (must be set at creation)
aws s3api create-bucket \
  --bucket locked-bucket \
  --object-lock-enabled-for-object-lock-configuration

# Set default retention
aws s3api put-object-lock-configuration \
  --bucket locked-bucket \
  --object-lock-configuration '{
    "ObjectLockEnabled": "Enabled",
    "Rule": {
      "DefaultRetention": {
        "Mode": "COMPLIANCE",
        "Days": 365
      }
    }
  }'
```

### Glacier Vault Lock

Lock the vault policy so it can never be changed. Used for compliance (e.g., WORM — Write Once Read Many).

## 4.21 S3 Encryption — SSE-S3, SSE-KMS, SSE-C

| Type | Key Management | Use Case |
|------|---------------|----------|
| **SSE-S3** | AWS manages keys (AES-256) | Default, simplest |
| **SSE-KMS** | You manage keys in KMS | Audit key usage via CloudTrail, key rotation control |
| **SSE-C** | You provide keys with each request | Full key control, keys never stored in AWS |
| **Client-Side** | You encrypt before upload | Maximum control, end-to-end encryption |

**SSE-C (Customer-Provided Keys) — Deep Dive:**

SSE-C requires you to send the encryption key with every request. AWS never stores your key.

```bash
# Generate a 256-bit encryption key
ENCRYPTION_KEY=$(openssl rand -base64 32)
KEY_MD5=$(echo -n "$ENCRYPTION_KEY" | base64 -d | openssl dgst -md5 -binary | base64)

# Upload with SSE-C (MUST use HTTPS)
aws s3api put-object \
  --bucket my-secure-bucket \
  --key sensitive-data.csv \
  --body sensitive-data.csv \
  --sse-customer-algorithm AES256 \
  --sse-customer-key "$ENCRYPTION_KEY" \
  --sse-customer-key-md5 "$KEY_MD5"

# Expected output:
# {
#   "SSECustomerAlgorithm": "AES256",
#   "SSECustomerKeyMD5": "abc123def456..."
# }

# Download with SSE-C (must provide the same key)
aws s3api get-object \
  --bucket my-secure-bucket \
  --key sensitive-data.csv \
  --sse-customer-algorithm AES256 \
  --sse-customer-key "$ENCRYPTION_KEY" \
  --sse-customer-key-md5 "$KEY_MD5" \
  downloaded-data.csv

# Without the key, you get AccessDenied
aws s3api get-object --bucket my-secure-bucket --key sensitive-data.csv out.csv
# Error: An error occurred (400) when calling the GetObject operation
```

**SSE-KMS Limitation:** S3 calls KMS `GenerateDataKey` (upload) and `Decrypt` (download) for every object. KMS has a quota of 5,500–30,000 requests/second per region. High-throughput S3 workloads can hit this limit. Solution: use S3 Bucket Keys to reduce KMS calls by up to 99%.

```bash
# Check current KMS request quota
aws service-quotas get-service-quota \
  --service-code kms \
  --quota-code L-6E3AF000

# Expected output:
# {
#   "Quota": {
#     "QuotaName": "Cryptographic operations (symmetric) request rate",
#     "Value": 10000.0
#   }
# }

# Enable S3 Bucket Keys to reduce KMS API calls
aws s3api put-bucket-encryption \
  --bucket my-kms-bucket \
  --server-side-encryption-configuration '{
    "Rules": [{
      "ApplyServerSideEncryptionByDefault": {
        "SSEAlgorithm": "aws:kms",
        "KMSMasterKeyID": "arn:aws:kms:us-east-1:123456789012:key/abcd-1234"
      },
      "BucketKeyEnabled": true
    }]
  }'

# Verify Bucket Key is enabled
aws s3api get-bucket-encryption --bucket my-kms-bucket
# Look for "BucketKeyEnabled": true
```

## 4.25 S3 Access Points & Object Lambda

### S3 Access Points

Simplify managing access to shared datasets. Each access point has its own DNS name and access policy.

```
Finance Team ──▶ Access Point (finance/) ──▶ S3 Bucket
Analytics Team ──▶ Access Point (analytics/) ──▶ S3 Bucket
```

```bash
# Create an S3 Access Point
aws s3control create-access-point \
  --account-id 123456789012 \
  --name finance-ap \
  --bucket my-shared-bucket \
  --vpc-configuration VpcId=vpc-0abcdef1234567890

# Expected output:
# {
#   "AccessPointArn": "arn:aws:s3:us-east-1:123456789012:accesspoint/finance-ap"
# }

# Set access point policy (restrict to finance/ prefix)
aws s3control put-access-point-policy \
  --account-id 123456789012 \
  --name finance-ap \
  --policy '{
    "Version": "2012-10-17",
    "Statement": [{
      "Effect": "Allow",
      "Principal": {"AWS": "arn:aws:iam::123456789012:role/FinanceRole"},
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:us-east-1:123456789012:accesspoint/finance-ap/object/finance/*"
    }]
  }'

# Use the access point to list objects
aws s3api list-objects-v2 \
  --bucket arn:aws:s3:us-east-1:123456789012:accesspoint/finance-ap \
  --prefix finance/

# List all access points for a bucket
aws s3control list-access-points --account-id 123456789012 --bucket my-shared-bucket
```

**Real-life use case:** A data lake bucket has data from 10 departments. Instead of one complex bucket policy, each department gets its own access point with a simple policy scoped to their prefix. VPC-restricted access points ensure data never leaves the VPC.

### S3 Object Lambda

Transform objects on-the-fly as they're retrieved. Uses Lambda to modify data before returning to the caller.

```
App ──▶ S3 Object Lambda Access Point ──▶ Lambda (redact PII) ──▶ S3 Bucket
```

```bash
# Create a supporting access point first
aws s3control create-access-point \
  --account-id 123456789012 \
  --name base-ap \
  --bucket my-bucket

# Create Object Lambda Access Point
aws s3control create-access-point-for-object-lambda \
  --account-id 123456789012 \
  --name redact-pii-ap \
  --configuration '{
    "SupportingAccessPoint": "arn:aws:s3:us-east-1:123456789012:accesspoint/base-ap",
    "TransformationConfigurations": [{
      "Actions": ["GetObject"],
      "ContentTransformation": {
        "AwsLambda": {
          "FunctionArn": "arn:aws:lambda:us-east-1:123456789012:function:redact-pii"
        }
      }
    }]
  }'

# Read through Object Lambda (PII is redacted automatically)
aws s3api get-object \
  --bucket arn:aws:s3-object-lambda:us-east-1:123456789012:accesspoint/redact-pii-ap \
  --key customer-data.json \
  redacted-output.json
```

**Lambda function example (redact SSN):**
```python
import boto3
import re

def handler(event, context):
    s3 = boto3.client('s3')
    # Get original object
    response = s3.get_object(
        Bucket=event['getObjectContext']['s3BucketArn'],
        Key=event['userRequest']['url'].split('/')[-1]
    )
    original = response['Body'].read().decode('utf-8')
    # Redact SSN pattern
    redacted = re.sub(r'\d{3}-\d{2}-\d{4}', '***-**-****', original)
    # Write transformed object back
    s3.write_get_object_response(
        Body=redacted,
        RequestRoute=event['getObjectContext']['outputRoute'],
        RequestToken=event['getObjectContext']['outputToken']
    )
```

**Real-life use case:** A healthcare company stores patient records in S3. The analytics team accesses data through an Object Lambda Access Point that automatically redacts PHI (names, SSNs, dates of birth). The raw data stays intact for authorized clinical users who access it through a regular access point.

### S3 Requester Pays

The requester (not the bucket owner) pays for data transfer and request costs. Useful for sharing large datasets.

```bash
# Enable Requester Pays on a bucket

aws s3api get-bucket-request-payment --bucket my-shared-dataset
# Expected output:
# { "Payer": "Requester" }

```

**Real-life use case:** A genomics research lab shares a 500 TB dataset with universities worldwide. With Requester Pays, each university pays for their own data transfer costs instead of the lab bearing the expense.

### S3 Express One Zone

Single-AZ, high-performance storage class. 10x faster than S3 Standard (single-digit millisecond latency). Use for ML training, financial modeling, media processing.

```bash
# Create a directory bucket (required for Express One Zone)
aws s3api create-bucket \
  --bucket my-fast-bucket--use1-az4--x-s3 \
  --create-bucket-configuration '{
    "Location": {"Type": "AvailabilityZone", "Name": "use1-az4"},
    "Bucket": {"Type": "Directory", "DataRedundancy": "SingleAvailabilityZone"}
  }'

# Upload to Express One Zone directory bucket
aws s3api put-object \
  --bucket my-fast-bucket--use1-az4--x-s3 \
  --key training-data/batch-001.parquet \
  --body batch-001.parquet

# Create a session for optimized repeated access
aws s3api create-session --bucket my-fast-bucket--use1-az4--x-s3
```

**Key differences from standard S3:** Directory bucket naming (`--az--x-s3` suffix), single-AZ only, no lifecycle rules, no versioning, no cross-region replication. Designed for compute-intensive workloads co-located in the same AZ.

### S3 Intelligent-Tiering

Automatically moves objects between tiers based on access patterns. No retrieval fees. Small monthly monitoring fee per object (~$0.0025 per 1,000 objects).

| Tier | Access Pattern | Latency |
|------|---------------|---------|
| Frequent Access | Default | ms |
| Infrequent Access | Not accessed for 30 days | ms |
| Archive Instant Access | Not accessed for 90 days | ms |
| Archive Access (optional) | Not accessed for 90+ days | 3-5 hours |
| Deep Archive Access (optional) | Not accessed for 180+ days | 12 hours |

```bash
# Upload object directly to Intelligent-Tiering
aws s3 cp large-dataset.csv s3://my-bucket/data/ --storage-class INTELLIGENT_TIERING

# Enable optional archive tiers
aws s3api put-bucket-intelligent-tiering-configuration \
  --bucket my-bucket \
  --id enable-archive-tiers \
  --intelligent-tiering-configuration '{
    "Id": "enable-archive-tiers",
    "Status": "Enabled",
    "Tierings": [
      {"AccessTier": "ARCHIVE_ACCESS", "Days": 90},
      {"AccessTier": "DEEP_ARCHIVE_ACCESS", "Days": 180}
    ]
  }'

# Check which tier an object is in
aws s3api head-object --bucket my-bucket --key data/large-dataset.csv \
  --query '{StorageClass:StorageClass,ArchiveStatus:ArchiveStatus}'

# Expected output:
# {
#   "StorageClass": "INTELLIGENT_TIERING",
#   "ArchiveStatus": null  (or "ARCHIVE_ACCESS" if archived)
# }

# Lifecycle rule to move ALL objects to Intelligent-Tiering
aws s3api put-bucket-lifecycle-configuration \
  --bucket my-bucket \
  --lifecycle-configuration '{
    "Rules": [{
      "ID": "move-to-intelligent-tiering",
      "Status": "Enabled",
      "Filter": {},
      "Transitions": [{"Days": 0, "StorageClass": "INTELLIGENT_TIERING"}]
    }]
  }'
```

**Real-life use case:** A SaaS company stores user-generated content (photos, documents) with unpredictable access patterns. Some files are accessed daily, others are forgotten. Intelligent-Tiering automatically optimizes costs without any lifecycle rule management, saving 30-40% compared to keeping everything in S3 Standard.

## 4.27 Key Takeaways

1. S3 is object storage with unlimited capacity and 11 nines durability
2. Use storage classes to optimize costs (Standard → IA → Glacier)
3. Enable versioning on important buckets
4. Use lifecycle rules to automate transitions and cleanup
5. Never make buckets public unless absolutely necessary (use presigned URLs)
6. Enable default encryption on all buckets
7. Use `aws s3 sync` for efficient directory synchronization
8. Bucket names are globally unique — use naming conventions
9. Configure CORS on the target bucket when cross-origin requests are needed
10. Use MFA Delete for extra protection on versioned buckets (root only)
11. Analyze S3 access logs with Athena for security auditing
12. Use CRR for cross-region DR, SRR for same-region log aggregation
13. Object Lock (Compliance mode) prevents deletion by anyone, including root
